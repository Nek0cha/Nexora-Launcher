# 公式サイト 設計

Nexora Launcher を紹介する公式サイトを `nexora.ny4n.net` に公開する。

## 1. 目的

- 来た人に、まずダウンロードしてもらう。次に、ほかのランチャーとの違いを見てもらう。
- オープンソースであることと、Apache-2.0（GPL の依存なし）であることを伝える。
- 1 ページの紹介サイトとする。ドキュメント、ブログ、お知らせは作らない。

## 2. 作らないもの、避けること

- クラッシュ診断を大きく扱わない。不安定な部分が残っているため、機能の一覧に「試験的」と添えて 1 行で載せるだけにする。比較表と最初の画面には出さない（利用者の判断）。
- 確かめていない比較を書かない。ほかのランチャーの記述は、すべて公開資料（公式サイト、リポジトリ、ライセンスのファイル）で確かめたものだけにする。
- 架空の数字（利用者数、ダウンロード数）や推薦文を載せない。
- Minecraft のロゴ、ブロックの絵、ドット絵の書体など、Mojang の商標や見た目を使わない。

## 3. コンセプト

- 誰に：ほかのランチャーで MOD を入れて遊んでいて、乗り換えを考えている人。あわせて、ライセンスを気にする開発者。
- どんな印象を：ひんやりした、静か、正直。
- 何で記憶に残すか：最初の画面のアプリの本物の画面（スクリーンショット）と、その下に続く仕様表のような比較表。比較表では Nexora の列だけを明暗の反転で示す。
- 種類：サイト系。
- テーマ：ダーク基本＋ライト対応。
- 動きの強さ：静か。
- 書体の組：S3（Hanken Grotesk ＋ Murecho。アプリと同じ書体）。比較表の数字は Spline Sans Mono を使う。
- 色：アプリのトークン（黒に近い地、アイコンの青緑 1 色のアクセント）を引き継ぐ。

## 4. ページの構成

1. ヘッダー：左にアイコンと名前、右に言語の切り替えと GitHub のリンク（アイコン＋スターの数は出さない）。
2. 最初の画面：一言の見出しと短い説明、ダウンロードのボタン（閲覧者の OS を推定して、その OS の配布物を主ボタンにする。ほかの OS は下に小さく並べる）、アプリのスクリーンショット。
3. 比較表：Nexora、Prism Launcher、Modrinth App、公式ランチャーの 4 列。行は調査のあとに決める（6 節）。ライセンスの行は必ず入れる。
4. 機能の一覧：README の機能から選ぶ。クラッシュ診断には「試験的」と添える。
5. 導入の注意：コード署名がないことによる Windows と macOS の警告と、その開き方（README から）。
6. フッター：ライセンス（Apache-2.0）、GitHub、Minecraft と Mojang に関係のない非公式のツールであることの表記。

日本語と英語の 2 ページを作る（`/` を英語、`/ja/` を日本語とし、ブラウザの言語で振り分けない。切り替えはヘッダーから）。

## 5. 作り方

- 技術スタック：Astro ＋ Tailwind CSS v4 の静的なサイト。理由は、1 ページで動く部分がほとんどなく、HTML を書き出すだけでよいため。
- 置き場所：このリポジトリの `site/`。`.github/workflows/ci.yml` に `paths-ignore: ["site/**", "docs/**"]` を足し、サイトだけの変更ではアプリの CI を走らせない。
- 公開先：Cloudflare Pages（`ny4n.net` の DNS が Cloudflare にあるため）。ルートのフォルダを `site`、ビルドのコマンドを `pnpm build`、出力を `dist` にする。`nexora.ny4n.net` はカスタムドメインとして Pages の画面でつなぐ（利用者の作業）。
- ダウンロードのリンク：ビルドの時点で GitHub の API から最新のリリースを読み、OS ごとの配布物の URL を埋め込む。読めなかったときは Releases のページへのリンクにする。新しいリリースを出したときにサイトを作り直すため、`release.yml` の最後で Cloudflare Pages のデプロイフック（リポジトリの Secrets に置く URL）を呼ぶ。フックが未設定なら何もしない。
- スクリーンショット：`docs/images/` のものを使う。足りなければ撮り直す。
- 検証：versatile-design の自動チェックで違反 0 件にし、1440px と 390px、ダークとライトのスクリーンショットで自己批評を最大 2 周行う。

## 6. 比較表の調査（作る前に行う）

Prism Launcher、Modrinth App、公式ランチャーについて、次の候補の行を公開資料で確かめ、出典の URL を `docs/research/` に残す。

- ライセンス（確認済みの見込み：Prism と Modrinth App は GPL-3.0、公式はソース非公開）
- インスタンス間の設定の共有（Nexora の共通設定）
- Minecraft のバージョンを上げる前の MOD の対応の確認
- ほかのランチャーからの取り込み
- `.mrpack` の読み込みと書き出し

確かめられなかった行は載せない。Nexora にしかない行が少なくても、正確さを優先する。

## 7. 作り手に任せること

- 見出しと説明の文章（`copy.md` に従い、README の事実から書く）。
- 機能の一覧に選ぶ項目と並び。
- ファビコン（アプリのアイコンから作る）。
